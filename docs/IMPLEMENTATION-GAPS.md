# 未実装・未完成の機能一覧

- 監査日: 2026-08-25
- 監査開始点: `main` の commit `d58f98d`
- 反映範囲: 上記commitの監査結果と、本変更で追加するカテゴリ削除の最終確認
- 対象: リポジトリへcommit済みの仕様書、production code、自動テスト、`package.json`

## この文書の読み方

この文書は「画面がある」「内部コードがある」だけで完成と判断せず、利用者が実際に一連の操作を完了できるか、仕様書の安全条件を満たすか、自動テストと人間の受入まで再現できるかを基準にしている。

- **未実装**: 中心となる処理がなく、利用者は目的を完了できない。
- **一部実装**: 画面または内部処理はあるが、仕様どおりの一連の操作にはならない。
- **受入未完了**: 機能コードはあっても、再実行可能なブラウザテストや人間の確認が完了していない。

現時点でも、ページの保存、URL指定保存、右クリック保存、ブックマークの一覧・編集・削除、カテゴリ・タグの基本管理、初回カテゴリ選択、キーワード検索などは利用できる。以下は、その状態から仕様書どおりの完成へ進むために残っている項目である。

## 利用者向け機能の未実装・未完成

### 1. Gemini Nanoによる自動タグ分類は旧方式のままである

**現在できること:** 保存後にGemini Nanoを呼び出し、既存の有効なタグ候補を使って分類する基本経路と、細分化度を選ぶ設定画面は存在する。

**残っていること:** 現在の実装は、細分化度ごとに新規タグ件数を制限する旧 `policyVersion: 1` で動いている。仕様書が定めるpolicy version 2の意味ベースの再利用、新規タグの重要度、正常候補だけの部分採用、最大3回の試行、中断復旧、旧設定からの移行がない。現行Gemini Nanoは分類が低速かつ不安定であり、実モデルを各条件で10回ずつ評価する仕組みに加え、prompt最適化、決定的なコードサニタイズ、別の端末内AIを同一条件で比較する仕組みも未実装である。

**利用者への影響:** 細分化度0〜4を選べても、表示されている説明どおりに短時間で安定して分類されるとはまだ保証できない。

追跡: [#13](https://github.com/anti-fact/Bookmation/issues/13)、[#16](https://github.com/anti-fact/Bookmation/issues/16)、[#71](https://github.com/anti-fact/Bookmation/issues/71)

### 2. AI自然言語検索は、最終候補をAIが選ぶ段階まで完成していない

**現在できること:** AIポップアップは質問を検索、製品ヘルプ、対象外の質問へ振り分ける。AIを利用できない場合もキーワード検索へ切り替えられる。

**残っていること:** AIが作るのは検索語までであり、画面に出す候補は通常のキーワード検索結果である。仕様にある「提示済みのIDとrevisionだけから、AIが複数候補を選ぶ」処理、候補数、応答時間、timeout時の扱いが確定・実装されていない。

**利用者への影響:** 自然な文章で検索できるように見えるが、意味に基づく候補選択の品質と安全性は完成していない。

追跡: [#17](https://github.com/anti-fact/Bookmation/issues/17)、[#18](https://github.com/anti-fact/Bookmation/issues/18)

### 3. 入力中の検索候補は動くが、正式な並び順が未確定である

**現在できること:** 完全一致、前方一致、部分一致を使い、カテゴリ・タグを優先して最大8件を表示する。IME入力中の検索抑止、キーボード選択、古い検索応答の破棄も実装されている。

**残っていること:** 日本語を含む検索語の正式な正規化、カテゴリ・タグ・ブックマークの件数配分、同点時の並び順を仕様書と固定fixtureへ反映する作業が残っている。

**利用者への影響:** 検索自体は使えるが、同じデータなら常に期待した順序になるという製品契約がまだ固まっていない。

追跡: [#41](https://github.com/anti-fact/Bookmation/issues/41)

### 4. カテゴリ削除とカテゴリ・タグ一覧にP0の残作業がある

**現在できること:** カテゴリ編集画面から専用の最終確認ダイアログを開き、対象カテゴリ名、削除する子タグの実名と件数、影響ブックマーク件数を確認してから、カテゴリ、子タグ、関連付けをまとめて論理削除できる。確認後に影響範囲が変わった場合は削除せず、最新内容を再表示して再確認を求める。

**残っていること:** AIを無効にしていても、削除されたカテゴリに関係するブックマークへ常に再分類Jobを作る。カテゴリ・タグ一覧は最大1000件の一括読込で、追加読込とトップへ戻る操作も未完成である。

**利用者への影響:** AIを無効にした意図が守られない可能性があり、大量のカテゴリ・タグも扱いにくい。

追跡: [#96](https://github.com/anti-fact/Bookmation/issues/96)

### 5. 自動アーカイブと復元は画面だけで、実データへ接続されていない

**現在できること:** 自動アーカイブのON/OFF、既定30日の入力、履歴権限の確認、アーカイブ一覧と複数選択復元の画面部品は存在する。

**残っていること:** 定期的に最終訪問日時を調べる処理、`ACTIVE` から `ARCHIVED` への変更、履歴がない項目の記録、実際のアーカイブ一覧読込と復元処理がない。実拡張では常に空のArchive Portを使用している。

**利用者への影響:** 設定をONにしてもブックマークは自動アーカイブされず、復元画面にも実データは表示されない。

追跡: [#25](https://github.com/anti-fact/Bookmation/issues/25)、[#26](https://github.com/anti-fact/Bookmation/issues/26)

### 6. 訪問リマインダーは集計できるが、任意権限と通知の導線が未完成である

**現在できること:** 7日、30日、365日の期間内で訪問日数を数え、未保存URLの候補を永続化し、Dashboardで「はい」「いいえ」「次回以降表示しない」へ回答できる。

**残っていること:** `history` がManifestの必須権限になっており、機能をONにした時だけ目的を説明して許可を求める仕様になっていない。`notifications` は任意権限として要求するが、候補発生をOS通知などで利用者へ知らせる処理が接続されていない。

**利用者への影響:** 機能を使わない利用者にも履歴権限を求める構成であり、候補ができてもDashboardを開かなければ気づけない。

追跡: [#101](https://github.com/anti-fact/Bookmation/issues/101)

### 7. QRコード・CSV共有とQR取込は未実装である

**現在できること:** 共有設定でカテゴリ、タグ、個別ブックマークを検索し、チェックボックスで選び、重複するブックマークIDを1件へまとめられる。

**残っていること:** QRコード生成、容量検査、CSV生成とdownload、QRのカメラ・画像読取、内容プレビュー、取込処理は存在しない。操作すると「現在利用できません」となる。

**利用者への影響:** 共有対象を選ぶところまでは進めるが、他の利用者へ渡したり受け取ったりはできない。

追跡: [#29](https://github.com/anti-fact/Bookmation/issues/29)

### 8. Google Drive同期・別アカウント共有は未実装である

**現在できること:** 共有設定にGoogle Driveの説明と未接続状態を表示できる。

**残っていること:** Googleアカウントの選択、OAuth、`appDataFolder`を使う同一アカウント端末同期、通常Drive fileを使う別アカウント共有、オフライン復帰、競合snapshotと利用者による解決がない。

**利用者への影響:** 端末間同期とGoogleアカウント間共有は利用できない。

追跡: [#100](https://github.com/anti-fact/Bookmation/issues/100)

### 9. Chrome標準ブックマーク取込は代替経路だけが一部実装されている

**現在できること:** ChromeからエクスポートしたHTMLファイルを選び、ブックマークと直上フォルダを解析し、内容と重複を確認してBookmationへ取り込める。同名の有効なタグがあれば、そのタグを再利用する。

**残っていること:** 仕様にあるChrome Bookmark APIと任意 `bookmarks` 権限を使う直接読込、新規タグに親カテゴリを選ぶ画面、同じ導線でのカテゴリ作成、全項目解決後の確定、途中再開がない。同名タグがないフォルダは、新規タグを作らず未分類として取り込む。

**利用者への影響:** HTML経由の基本取込はできるが、仕様どおりの分類を確認してから取り込むことはできない。

追跡: [#33](https://github.com/anti-fact/Bookmation/issues/33)

## データ保護とリリース準備の未完成

### 10. 保存データの完全なruntime検証と破損隔離がない

**現在できること:** 一部の書込みでは、JSONとして保存可能か、最大サイズを超えないか、既知のschema versionかを検査する。

**残っていること:** Storeごとの全項目を検査するruntime schema、読込時の検証、未知versionや破損recordを通常データから隔離する処理、中断再開可能なmigrationがない。訪問リマインダー、Blob、端末設定を含む全保存先で統一されていない。

**利用者への影響:** 更新失敗や破損データが発生した場合、安全に問題のある1件だけを隔離して残りを利用する保証が不足している。

追跡: [#97](https://github.com/anti-fact/Bookmation/issues/97)

### 11. mainの品質コマンドが全件成功しない

2026-08-25の監査結果は次のとおりである。

| コマンド         | 結果 | 内容                                                                |
| ---------------- | ---- | ------------------------------------------------------------------- |
| `pnpm build`     | 成功 | Chrome MV3成果物を生成できる                                        |
| `pnpm lint`      | 失敗 | 28件の既存ESLint errorがある                                        |
| `pnpm typecheck` | 失敗 | 標準ブックマーク取込の `flatMap` に型エラーが1件ある                |
| `pnpm test`      | 失敗 | 435/436件成功。1件がリポジトリ外の個人DownloadsにあるHTMLを参照する |

**利用者・開発者への影響:** buildが成功しても、mainが静的検査と全自動テストを通過した状態ではない。別環境では個人ファイルがないため同じテスト結果を再現できない。

追跡: [#98](https://github.com/anti-fact/Bookmation/issues/98)
