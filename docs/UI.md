# UI 設計

- 状態: 実装前の設計基準
- 更新日: 2026-08-14
- UI 技術: Plasmo（React）+ Tailwind CSS
- 関連: [全体設計](./DESIGN.md) / [フロントエンド](./FRONTEND.md) / [要件](./REQUIREMENTS.md)

## UI の目的

Bookmation は、Chrome 標準ブックマークとは別の保存領域へページを素早く追加し、重なりを許すメインタグとサブタグから後で見つけ直す拡張機能である。保存操作は短く、AI の分類結果は確認・修正可能にする。探す操作では、タグをたどる方法と自然言語で候補を得る方法の両方を提供する。

## UI で使う用語と規則

| 用語 | UI 上の意味 |
| --- | --- |
| メインタグ | 利用者だけが作成できる中心テーマ。AI は既存タグを選べるが、新規作成できない |
| サブタグ | 補足的な特徴。利用者が作成でき、AI は既存の利用者定義タグを優先し、適切な候補がない場合だけ新規作成できる |
| タグの重なり | 1件のブックマークにメインタグとサブタグをそれぞれ複数付与でき、同じタグを複数のブックマークで再利用できること |
| メインタグ未設定 | 既存メインタグを選べない、または利用者がまだ選んでいない状態。保存失敗ではない |
| AI タグ | AI が新規作成したサブタグ。`AI` の文字ラベルを付け、利用者が編集・削除できる |

タグは表示名ではなく ID で識別する。同じ表示名のタグが存在しても自動統合せず、種類、作成元、利用件数などの文脈を併記して区別する。タグ作成時は既存候補を先に出すが、重なりを理由に既存タグへの関連付けを拒否しない。

AI 細分化度は、AI が**新規作成するサブタグ**だけを制御する。どの設定でも AI はメインタグを作成せず、既存の利用者定義サブタグを先に評価する。

## 画面と遷移

### 拡張機能ポップアップ

ツールバーの拡張機能アイコンをクリックすると、小さなポップアップに次の2操作を常に同じ順序で表示する。

1. `このページをブックマーク`
2. `Bookmation ホームを開く`

ポップアップを開いただけでは保存しない。1つ目の操作は現在のアクティブタブを保存し、2つ目は拡張機能ページの `ホーム` を開く。Bookmation のホームが既に開いている場合は同じタブへフォーカスし、不要なタブを増やさない。

`chrome://` など保存対象にできないページでは、保存ボタンを無効化し、理由を短く表示する。ホームを開く操作は利用できる状態を保つ。

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 保存可能 | 現在ページのタイトルとドメイン | 保存、ホームを開く |
| 保存中 | `保存しています` と進捗表示 | 二重送信を防止する |
| 保存済み | `保存しました` | ホームで確認、元に戻す |
| 既に保存済み | `既に保存されています` | 保存済み項目を開く、タグを編集 |
| 保存不可 | 保存できない理由 | ホームを開く |
| 失敗 | データが保存されていないこと | 再試行、ホームを開く |

### ショートカット

Chrome の commands として次の2操作を別々に提供する。

- `現在のページをブックマーク`
- `Bookmation ホームを開く`

設定画面には、Chrome に実際に割り当てられたキーを表示し、`chrome://extensions/shortcuts` で変更できることを案内する。未割り当ての場合はその事実を表示する。保存ショートカットの実行結果はツールバーアイコンの一時バッジと、次回ホーム表示時の状態で確認できるようにする。保存できないページでは失敗理由を後から確認できるようにする。

### 拡張機能ページ

実装上は1つの Plasmo のタブページを React の画面状態で切り替える。戻る・進む・再読込で安全に復元できる画面種別、選択タグ、表示形式は hash route と query に表現する。自然言語の検索文は閲覧意図を含み得るため URL や永続設定へ入れず、画面を開いている間の状態として扱う。

| route | 画面 | 主な内容 |
| --- | --- | --- |
| `#/home` | ホーム | 最近追加したブックマークを保存日時の降順で表示 |
| `#/bookmarks?tag=<tagId>` | タグ別一覧 | 右サイドメニューまたはタグ候補から選んだタグのブックマーク一覧 |
| `#/search?target=tags` | タグ検索 | 自然言語に合うタグ候補を複数表示 |
| `#/search?target=bookmarks` | ブックマーク検索 | 自然言語に合うブックマーク候補を複数表示 |
| `#/bookmark/<bookmarkId>` | ブックマーク詳細 | 検索候補または一覧から選んだ1件の情報、全タグ、編集操作 |
| `#/add-url` | URL 追加 | URL 指定保存の入力・確認。元画面の上にダイアログとして表示可能 |
| `#/settings` | 設定 | AI 細分化度、表示初期値、ショートカット案内、データ管理 |

検索対象は query に保持できるが、検索文、ページカーソル、AI の内部入力、個人情報を含む説明文は URL に入れない。再読込で検索文が失われることは、既定で検索履歴を残さない安全側の挙動とする。

## ホームと一覧のレイアウト

初期表示は `ホーム` であり、見出しを `最近追加したブックマーク` とする。検索条件やタグ条件は付けず、保存日時の新しい順に表示する。0件の場合は、ツールバーボタン、保存ショートカット、URL 追加の3導線を示す。

デスクトップの拡張機能ページは次の3領域で構成する。

| 領域 | 内容 |
| --- | --- |
| 上部固定バー | ホーム、URL 追加、自然言語検索、並び替え、3表示切替、密度 |
| 中央 | 画面見出し、適用中の条件、件数、ブックマーク一覧、追加読込、空・エラー状態 |
| 右追従サイドメニュー | メインタグ、サブタグ、件数、選択状態、タグ管理 |

右サイドメニューは一覧をスクロールしても画面内に追従し、メニュー内部だけをスクロールできるようにする。狭い画面では `タグ` ボタンから開くドロワーへ変形する。閉じても選択タグを保持し、中央上部に選択中のタグを再掲する。

## 右サイドタグメニュー

右サイドメニューの先頭に `最近追加` と `すべて` を置き、その下を `メインタグ` と `サブタグ` の2セクションに分ける。厳密な親子ツリーにはせず、タグの種類と重なりを保ったまま一覧表示する。

- メインタグには `メインタグを作成` を表示する。作成は必ず利用者の明示操作で行う。
- サブタグには `サブタグを作成` を表示する。利用者作成と AI 作成を併記し、AI 作成だけ `AI` ラベルを付ける。
- 各タグに紐づくブックマーク件数を表示する。
- タグを選ぶと `#/bookmarks?tag=<tagId>` へ移動し、中央の見出し、件数、一覧を更新する。
- 選択中タグには見た目の選択状態と `aria-current` を付ける。
- 同名タグは種類と補足文脈を併記し、表示名だけで同一視しない。
- タグが多い場合はメニュー内の絞り込み入力、折りたたみ、`さらに表示` を使い、一度に全件を描画しない。

タグ選択は一覧の表示条件であり、ブックマークに別のタグが付いていても対象から除外しない。選択したタグ ID が付いた項目をすべて表示する。

メイン／サブの作成フォームでは、入力中の名称と完全一致・類似する既存タグを、種類、作成元、利用件数付きで先に提示する。既存候補を選んで再利用できる一方、同名タグが意図した別概念であれば、利用者が `同名の別タグとして作成` を明示選択して新しい ID を作成できる。AI がこの確認を代行したり、メインタグを作成したりしない。ブックマーク編集画面からも同じ作成フォームを開ける。

## 自然言語検索

上部検索は `タグを探す` と `ブックマークを探す` の2択を持つ。選択に応じてプレースホルダー、候補の内容、遷移先を変える。

### タグを探す

例: `React の画面設計に使えそうなもの`

- メインタグとサブタグから意味的に近い候補を複数表示する。
- 候補行にタグ名、`メイン` または `サブ`、件数、短い一致理由を表示する。
- 候補を選ぶと該当タグのブックマーク一覧へ移動する。最上位候補へ自動遷移しない。
- 一致する候補が複数ある場合は少なくとも複数件を提示し、上位候補だけに決め打ちしない。

### ブックマークを探す

例: `先週保存した React のパフォーマンスの記事`

- タイトル、URL、保存日時、付与タグ、利用可能なページ情報から候補を複数表示する。
- 候補行にタイトル、ドメイン、保存日時、タグ件数、短い一致理由を表示する。タグ名は候補内の開閉操作で全件を確認する。
- 候補の選択は Bookmation 内の詳細を開く操作とし、外部ページは `元ページを開く` という別操作から開く。
- `すべての候補を見る` で検索結果画面へ移動し、表示形式を切り替えられる。

検索候補は combobox と listbox のパターンで実装し、上下キー、Enter、Esc で操作できるようにする。日本語 IME の変換中は検索を確定しない。入力中、検索中、モデル準備中、候補あり、0件、AI利用不可、再試行可能な失敗を区別する。

AI が利用できないときは自然言語検索を成功したように装わず、タイトル、URL、タグ名によるローカル文字列検索の候補であることを明示する。ブックマーク内容を外部サービスへ送らない。

## URL を指定して保存

上部の `URL を追加` から入力画面を開く。

1. 利用者が `https://` または `http://` の URL を入力する。
2. URL の形式を検証し、取得できる範囲でタイトル、ドメイン、ファビコン、サムネイル候補を表示する。
3. 利用者が内容を確認して `ブックマークに追加` を実行する。
4. Bookmark を先に保存し、その後に既存メインタグの候補提示とサブタグ分類を行う。
5. 保存後は `ホームで見る`、`タグを編集`、`元に戻す` を表示する。

メタデータを取得できなくても URL 自体が有効なら、URL をタイトルの代替として保存できる。重複 URL を検出した場合は既存項目を示し、タグの追加・既存項目を開く・別項目として保存する、の選択肢を出す。黙って上書きしない。

## 表示形式

表示形式は、文字付きの3択セグメントコントロール `リスト / グリッド / 弁当` で切り替える。切替時も、route、検索語、選択タグ、並び順、スクロール復元情報を保つ。

| 形式 | 表示 | 密度 |
| --- | --- | --- |
| リスト | 小型画像、タイトル、ドメイン、保存日時、タグ要約を1件1行で比較する | 1列固定。密度選択は表示しない |
| グリッド | 同一幅・同一基本比率のカードで比較する | `自動 / 2 / 3 / 4 / 5 / 6` から1行の列数を選ぶ |
| 弁当 | 小カードと大カードを決定的な CSS Grid パターンで配置する | `自動 / 2 / 3 / 4 / 5 / 6` を基準列数として選ぶ |

弁当の大カードは利用者のピン留め、または固定の繰返しパターンで決める。AI の確信度を重要度として使わない。DOM 順と視覚順を一致させる。画面幅に収まらない指定値は実表示だけ安全な列数へ縮退させ、利用者の設定値は保持する。

一覧はカーソル方式で追加読み込みする。自動読込だけに依存せず `さらに読み込む` を併設し、現在件数と総件数を表示する。

## ブックマークカードとタグ展開

すべての表示形式で、次の情報と操作を提供する。

- タイトル、ドメイン、ファビコン、取得済みの場合のサムネイル
- 保存日時、保存・分類状態
- `タグを表示（合計 N 件）` 開閉ボタン。閉じた状態では種類を偏らせず件数だけを示す
- `詳細`、`元ページを開く`、`編集`、`再分類`、`アーカイブ`、`削除`

タグ開閉ボタンを展開すると、そのブックマークに付いた**すべてのメインタグとサブタグ**を種類別に表示する。メインタグも複数件を許容し、AI 作成サブタグには文字ラベルを付ける。閉じた状態ではタグ名を表示せず `タグ N件` だけを示し、タグがない場合は `タグなし` とする。

開閉ボタンには `aria-expanded` と `aria-controls` を設定する。展開でカード高が変わってもフォーカスを失わず、再読込や表示形式切替で意図しない外部ページ遷移を起こさない。

## AI サブタグ細分化スライダー

設定画面と保存確認面に `AI が作るサブタグの細かさ` を表示する。1〜5の離散値とし、数値だけでなく意味と新規作成上限を併記する。

| 値 | ラベル | 1回の分類で AI が新規作成できるサブタグ上限 |
| --- | --- | --- |
| 1 | 既存のみ | 0 |
| 2 | 粗い | 1 |
| 3 | 標準 | 2 |
| 4 | 細かい | 4 |
| 5 | 詳細 | 6 |

現在値の下に `既存の利用者定義サブタグを優先し、適切な候補がない場合に最大2件を作成します。メインタグは作成しません。` のような予告文を出す。

- 値に関係なく、AI はメインタグを作成・改名・削除しない。
- 値に関係なく、既存の利用者定義サブタグを新規作成より先に評価する。
- 設定変更は過去のブックマークを自動再分類しない。
- 再分類するときは対象と件数を別途確認する。

## 主要フロー

### 現在ページを保存する

1. 拡張機能ポップアップまたは保存ショートカットから保存を実行する。
2. Bookmark をローカルに保存し、成功を先に通知する。
3. 既存メインタグがあれば複数候補を提示するが、AI が新規メインタグを作ることはない。
4. 既存の利用者定義サブタグを優先して分類し、なければ細分化度の範囲内で AI サブタグを作成する。
5. 利用者はタグを追加・解除・編集できる。候補を確定しなくても Bookmark は残る。

### タグから探す

1. ホームの右サイドメニューでメインタグまたはサブタグを選ぶ。
2. タグ別一覧へ移動し、選択タグ、件数、適用条件を確認する。
3. リスト・グリッド・弁当と、必要な場合は列数を切り替える。
4. カードのタグを展開して重なりを確認し、詳細または元ページを開く。
5. 戻ったときにタグ条件、表示形式、スクロール位置を復元する。

### 自然言語から探す

1. 検索対象を `タグ` または `ブックマーク` から選ぶ。
2. 自然な文章を入力する。
3. 複数候補と一致理由を確認する。
4. タグ候補ならタグ別一覧、ブックマーク候補なら Bookmation 内の詳細へ進む。
5. 外部ページは明示した `元ページを開く` から開く。

## 状態設計

| 状態 | 表示と回復 |
| --- | --- |
| 初回・0件 | ポップアップ、2つのショートカット、URL 追加の保存方法を示す |
| 最近追加0件 | データ自体が0件か、アーカイブを除いた結果かを区別する |
| タグ0件 | `メインタグを作成` と、タグ未設定でも保存できることを示す |
| 絞り込み0件 | 選択タグまたは検索条件と `条件を解除` を示す |
| 自然言語検索中 | 検索対象と処理中であることを示し、古い候補と混同させない |
| AI 非対応 | 文字列検索と手動タグ付けを使えることを示す |
| モデル取得中 | 進捗が取得できる場合は表示し、保存済みデータを維持する |
| AI 分類失敗 | `メインタグ未設定` で保存済みであること、再試行、手動編集を示す |
| サムネイル失敗 | レイアウトを保つ代替面を表示する |
| 追加読込失敗 | 読込済み項目を維持し、その位置に再試行を置く |
| オフライン | 保存・一覧・文字列検索を継続し、利用できない AI 機能だけを区別する |

## 受け入れ条件

- 拡張機能アイコンをクリックすると、保存を自動実行せず、`このページをブックマーク` と `Bookmation ホームを開く` の2操作が表示される。
- 現在ページ保存とホーム表示の2ショートカットが独立して動作する。
- ホームの初期一覧が保存日時降順の最近追加ブックマークである。
- URL だけを指定して保存でき、メタデータ取得失敗時も利用者確認後に保存できる。
- 右サイドメニューがデスクトップで追従し、タグ選択後に対応するブックマーク一覧へ移動する。
- 1件のブックマークにメインタグとサブタグをそれぞれ複数付与でき、同じタグを他のブックマークでも再利用できる。
- 右サイドメニューまたはブックマーク編集からメイン／サブタグを手動作成でき、同名候補を確認した上で別 ID として作成できる。
- AI がメインタグを新規作成する UI、処理、成功表示がない。
- AI は利用者定義サブタグを優先し、細分化度の上限内でだけ新規サブタグを作る。
- タグ検索とブックマーク検索が区別され、どちらも一致する候補を複数表示して利用者に選ばせる。
- 一覧条件を保ったままリスト・グリッド・弁当を切り替えられる。
- グリッドと弁当だけに1行の表示数を選ぶコントロールが表示される。
- 各カードからすべてのメインタグとサブタグを展開できる。
- キーボードだけで保存、ホーム表示、検索候補選択、タグ選択、表示切替、タグ展開を完了できる。

## アクセシビリティ確認項目

- ポップアップの2操作には明確なボタン名があり、初期フォーカスで誤保存しない。
- 検索対象の切替はラジオグループ、候補は combobox / listbox として状態を通知する。
- セグメント、スライダー、開閉ボタン、ドロワーの状態を支援技術へ通知する。
- Tab 順序と視覚順を一致させ、弁当表示でも DOM 順を崩さない。
- フォーカスリングを消さず、カード全体リンクと内部操作を重ねない。
- 200% 拡大時に検索、タグメニュー、保存操作が隠れない。
- 選択、AI 由来、警告を色だけで伝えない。
- `prefers-reduced-motion` を尊重する。
- 追加読込件数、保存結果、検索結果件数を適切な live region で通知する。
