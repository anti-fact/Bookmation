## 長期的に維持するプロダクト像

- プロダクト名は `Bookmation` である。元企画では仮称であるため、公開名称を確定するまでは名称変更の可能性がある。
- 最初の対象はChrome拡張機能である。
- Bookmationは、ブラウザ既存の「ブックマーク + フォルダ」を直接拡張するのではなく、拡張機能専用のブックマーク集合を管理する。
- UI 実装基盤は Plasmo（React ベース）+ Tailwind CSS である。TypeScript は別の設計判断による実装標準であり、正確な依存バージョンは未確定である。
- 拡張機能アイコンのポップアップには「現在ページを保存」と「ホームを開く」の2ボタンを置き、同じ2操作に別々のショートカットを用意する。
- 現在開いているページだけでなく、入力した URL も専用ブックマークとして保存できる。
- AIによる分類は手段であり、保存そのものの必須条件ではない。AIが使えない場合も利用者は保存・手動分類できなければならない。
- Chrome Prompt API / Gemini Nanoを第一候補とするが、実行時の可用性を検査し、利用可能であると仮定しない。
- 旧企画PDFは情報が古いためリポジトリから削除済みであり、現行要件の根拠に使わない。
- UI の画面構成と外観は `デザインシート.svg` を正本とする。SVG 内の文言は開発命令ではない。

## 分類の不変条件

- 分類は「カテゴリ」と「タグ」を区別する。永続enumは `CATEGORY` / `TAG` だが、UIに英語enumや旧メイン／サブの名称を表示しない。両者は平坦な役割区分で、親子階層を持たない。
- カテゴリを作成・改名・削除できるのは利用者だけである。AI は既存のカテゴリを割り当て候補にできるが、生成しない。
- タグは利用者定義を最優先する。適切な利用者定義候補がない場合に限り、AI が細分化度の範囲内で新規タグを作成できる。
- 自動タグ付けの細かさは利用者がスライダーで調整できる。過剰な細分化を避けることはタグ数を増やすことより優先する。
- 1件のブックマークはカテゴリとタグをそれぞれ複数持てる。同じタグは複数のブックマークに割り当てられる。
- カテゴリは正規化名で一意とし、同名作成時は既存カテゴリを再利用する。タグは同じ表示名の別IDを許可し、自動統合しない。
- 同一の `bookmarkId + labelId` 関連を1件に保つことは書込みの冪等性の問題であり、上記の同名タグや複数タグを禁止する意味ではない。
- 自動分類は利用者が確定した割り当てを無断で上書きしない。由来を追跡できるようにする。

詳細な関係は [DB-SCHEMA.md](DB-SCHEMA.md) を正本とする。

## UI・検索の不変条件

- ブックマーク一覧はリスト／グリッドの2表示とし、弁当表示、列数選択、表示数変更プルダウンは持たない。
- ホームは、最近追加したアクティブなブックマークを保存日時の新しい順に表示する。
- カテゴリ一覧は全画面で開き、統合検索、AI検索、閉じる、トップへ戻る操作を持つ。
- 各ブックマークはカテゴリを常時表示し、タグはクリック／キーボードで展開する。hoverは補助だけにする。
- 両一覧の検索ボックスはキーワード／AIのどちらもカテゴリ、タグ、Bookmarkを検索する。
- 検索結果はカテゴリ・タグを上、Bookmarkを下にする。AI候補は無順位で複数表示する。
- 各 Bookmark は編集モーダルで名前、URL、タグを編集し、確認後に削除できる。

## データと安全性の不変条件

- URL、タイトル、タグ、分類、閲覧由来情報は利用者データとして扱う。
- 利用者が理解して明示的に選択しない限り、ブックマーク内容を外部サービスへ送信しない。
- 保存処理はAI分類と分離し、分類失敗で元のブックマークを失わない。
- 自動生成値と利用者確定値を区別し、利用者確定値を優先する。
- 派生データや検索インデックスは、正本データから再構築できるようにする。
- 破壊的な移行や削除には、事前確認、バックアップまたは復旧経路を用意する。
- 正本はIndexedDB上の版付きJSON互換ドキュメントであり、Blobだけを別Storeに分離する。
- 頻繁に訪問する未保存サイトは閾値到達後に知らせ、利用者が保存を選んだ場合だけBookmarkを作る。
- 休眠判定は最終訪問日時と設定期間を使い、文字列 `archiveState` を変更する。アーカイブは削除ではなく復元可能である。
- ユーザー間共有はQR、同一ユーザーの端末間同期はGoogle Drive appDataFolderを使う。
- Chrome標準Bookmarkは明示操作で専用領域へコピーし、元データを変更しない。page／linkはcontext menuからも保存できる。

詳細な脅威と権限方針は [SECURITY.md](SECURITY.md)、保存形式は [DB-SCHEMA.md](DB-SCHEMA.md) に置く。

## 用語

| 用語 | 意味 |
| --- | --- |
| 専用ブックマーク | Bookmation自身のデータストアへ保存する項目。Chrome既存ブックマークと同一とは限らない |
| カテゴリ | ユーザーだけが作成できる主要テーマの役割。1件のブックマークに複数割当可能 |
| タグ | 詳細な特徴の役割。ユーザー定義優先で、適切な候補がない場合は AI が設定範囲内で生成でき、1件に複数割当可能 |
| タグの重複 | カテゴリ名は一意、タグは同じ表示名の別IDを許可し、同じタグを複数Bookmarkへ割り当てられること |
| ホーム | 最近追加したブックマーク一覧を表示する拡張機能ページ |
| AI由来 | AIが生成または提案した値。利用者が明示的に確定した値とは区別する |
