# 制約

- 状態: 要件由来の固定条件と、実装開始時の設計境界
- 基準日: 2026-08-14

## 判断の境界

- 今回の依頼は添付 PDF より新しく、競合時に優先する。
- PDF の「確定事項」と「仮案」を同じ確度で扱わない。
- 参考 UI の外見や挙動を複製せず、観察した設計パターンだけを利用する。
- リポジトリにはまだ実装がない。Plasmo（React ベース）+ Tailwind CSS の採用は確定要件であるが、動作確認済みではない。TypeScript は別の設計判断による実装標準であり、正確な依存バージョンは未確定である。

## 固定するプロダクト制約

1. 初期提供先はデスクトップ版 Chrome の Manifest V3 拡張機能である。
2. ブックマークは Bookmation 専用データであり、ブラウザ標準のブックマークとフォルダを正本にしない。
3. 分類は「メインタグ」と「サブタグ」の平坦な役割区分だけで表す。大カテゴリ、小カテゴリ、タグ間の親子階層を追加しない。
4. メインタグを作成・改名・削除できるのはユーザーだけである。AI は候補の既存 ID を割り当てられるが、メインタグを生成しない。
5. サブタグはユーザー定義候補を最優先する。適切な候補がない場合だけ、AI は細分化スライダーの上限内で新規サブタグを作成できる。
6. 1件のブックマークに MAIN / SUB をそれぞれ複数割り当てできる。同じタグは複数のブックマークに割り当てできる。
7. 同じ表示名のタグレコードを許可する。同名だけを根拠に一意性制約、作成拒否、自動統合を行わず、ID、MAIN / SUB、作成元、件数で識別する。同一の `bookmarkId + tagId` 関連は冪等性のため1件とし、これをユーザーが求めるタグ重複の禁止とは扱わない。
8. タグ一覧はデスクトップの右サイドメニューに置き、選択したタグのブックマーク一覧へ移動する。PDF p.8 の左フォルダツリーは採用しない。
9. 一覧はリスト・グリッド・弁当の3形式を持つ。グリッドと弁当だけに1行の表示数選択を出す。
10. 各ブックマークのタグは展開表示とし、展開後に複数の MAIN / SUB を確認できる。
11. 自然言語のタグ検索とブックマーク検索を別の結果種別とし、どちらも複数候補を表示する。
12. 拡張機能アイコンは「現在ページを保存」と「ホームを開く」の2ボタンを表示する。同じ操作に別々のショートカットを用意する。
13. 現在ページだけでなく、ユーザーが入力した URL を保存できる。
14. ホームは最近追加したブックマークを保存日時の新しい順に表示する。
15. AI が使えなくても、保存、右サイドメニューでの探索、手動整理は継続できる。

PDF p.10 の決定に従い、フロントエンドとバックエンド相当のコードはこの単一リポジトリで管理する。MVP にリモートサーバーがない間も、UI、Service Worker、ドメイン、保存アダプターを別リポジトリへ分割しない。

## AI と実行環境の制約

- P0 の AI は Chrome Prompt API が提供する Gemini Nano を使い、ページ情報を端末外へ送信しない。
- Prompt API は 2026-08-14 に確認した公式仕様では Web Worker から利用できない。Manifest V3 Service Worker は保存とジョブ永続化だけを担当し、AI セッションは対応を実機確認したトップレベルの拡張機能ドキュメントで実行する。
- 利用前に `LanguageModel.availability()` 相当で可用性を判定する。モデル未取得、ダウンロード中、端末非対応を別状態として表示する。
- 公式資料の 2026-08-14 時点の記載では、基盤モデル系 API には OS、空き容量、RAM/CPU または GPU、初回モデル取得用ネットワークの条件がある。条件は Chrome 更新で変わるため、固定値をコードへ散在させない。
- 日本語入出力対応と必要 Chrome バージョンは実装スパイクで再確認し、`minimum_chrome_version` を決める。
- Dashboard、Side Panel 等のどの拡張機能ドキュメントを AI host とするか、ユーザー操作をモデル取得へ正しく引き継げるかは、[ISSUES.md](ISSUES.md) の ISSUE-001 で確定する。Offscreen Document が使えるとは事前に仮定しない。
- AI 出力は信頼しない。JSON Schema とドメイン検証を通し、候補外のメインタグ ID、AI が生成したメインタグ、上限超過サブタグ、危険な文字列を拒否する。
- Web ページの文字列は命令ではなく分類対象データである。本文全体を無制限にプロンプトへ入れない。
- P0 は外部 AI API を自動フォールバックにしない。非対応時のフォールバックは手動分類である。

詳細は [SECURITY.md](SECURITY.md) を参照する。

## データと同期の制約

- ドメインデータの正本はローカル IndexedDB、少量の設定は `chrome.storage.local` とする設計である。
- `chrome.storage.sync` の小さいクォータをブックマーク本体の正本にしない。
- 拡張機能を削除するとローカルデータが失われ得る。P0 では削除前の警告を制御できないため、エクスポートと P1 同期をデータ保全策として計画する。
- P1 の Google Drive 同期は利用者が明示的に接続する。認証トークンをドメインDBやログへ保存しない。
- 同期は削除を即時物理削除にせず tombstone を使い、競合時にどちらかの編集を黙って捨てない。
- QR には秘密情報、OAuth トークン、閲覧履歴、ローカル内部 ID を入れない。容量超過時にデータを切り捨てない。

## 権限制約

- P0 は `storage`、`activeTab`、必要な場合の `scripting` を中心にし、常時の全サイト host permission を避ける。`commands` には現在ページ保存とホーム表示の2操作を別々宣言する。
- `bookmarks` 権限は P0 では不要である。
- `history` は P1 の訪問回数・最終訪問日時機能だけで任意取得する。拒否されても P0 を利用できる。
- `notifications`、`identity`、Google OAuth scope は該当 P1 機能を有効にするときだけ要求する。
- Manifest V3 に従い、実行コードは拡張機能パッケージへ同梱する。外部から取得した JavaScript や WASM を実行しない。

## UI・アクセシビリティ制約

- 表示形式は現在値が見えるセグメントコントロールを第一候補とする。
- 細分化スライダーは数値だけでなく「粗い・標準・細かい」等の意味と作成上限を示す。
- 自然言語検索はタグ候補とブックマーク候補を視覚的・意味的に分け、複数候補をキーボードで選択できる。
- 同名タグは種類、作成元、関連件数等を併記し、名前だけで誤選択させない。
- 選択、AI 由来、エラーを色だけで表現しない。
- ホバーだけに操作を隠さず、フォーカス時とタッチ相当操作でも利用可能にする。
- 弁当表示でも DOM 順序と視覚上の読み順を一致させる。
- 自動追加読込だけに依存せず「さらに読み込む」を用意する。
- 狭い画面では右サイドバーをドロワーまたは下部シートにするが、フィルター状態は維持する。

## 現時点で固定しないもの

- 依存ライブラリの正確なバージョンとパッケージマネージャー
- サムネイル取得方式と保存容量上限
- 自動提案の訪問回数、アーカイブまでの日数
- 弁当カードの大小を決めるルール
- QR のエンコード形式と一度に共有できる件数
- Drive 同期ファイル形式、暗号化、競合UI
- ハッカソンの締切、審査基準、デモ時間

これらは [ISSUES.md](ISSUES.md) で追跡し、決定後に本書と [MEMORY.md](MEMORY.md) を更新する。
