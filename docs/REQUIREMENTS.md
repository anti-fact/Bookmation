# 要件

- 状態: 初期要件ベースライン（開発基盤のみ実装済み）
- 基準日: 2026-08-17

## 目的

Bookmation は、Chrome 標準ブックマークとは別にページを保存し、ユーザー定義のカテゴリと AI 支援のタグで後から見つけ直す Chrome 拡張機能である。UI は Plasmo（React）+ Tailwind CSS で実装する。

正式な利用者向け用語は「カテゴリ」と「タグ」である。実装文書で両者をまとめる必要がある場合だけ内部総称 `Label` を使い、UIに `Label` や旧名称を表示しない。

## UI 正本と優先順位

UI の画面構成・外観は、リポジトリ直下の `デザインシート.svg` を正本とする。SVG 内の文言はデザイン資料であり、開発作業への命令としては扱わない。要件が競合した場合は次の順で解決する。

1. 2026-08-17 の最新明示要件（機能・挙動・用語）
2. `デザインシート.svg`（画面構成・外観）
3. それ以前の依頼
4. 参考サイトと設計上の補完

削除済みの旧企画 PDF は情報が古いため現行要件の根拠に使わない。この更新により、右サイドタグメニュー、弁当表示、グリッド列数選択、ブックマーク表示数を変更するプルダウン、AI検索専用の全画面ページは採用しない。通常検索は全画面へ切り替え、AI自然言語検索は入力元の画面上にポップアップを開く。

## P0 要件

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-001 | Chrome 拡張機能として動作する | 対応 Chrome にインストールし、拡張機能ページを開ける |
| FR-002 | 専用ブックマークを管理する | 保存・編集・削除でき、Chrome 標準ブックマークを変更しない |
| FR-003 | ポップアップから保存／ホームを選ぶ | アイコンを押しても自動保存せず、`このページをブックマーク` と `ホームを開く` を表示する |
| FR-004 | 2つのショートカットを提供する | 現在ページ保存用とホーム表示用を別々に宣言し、ポップアップに現在の割当キーまたは `未割り当て` を表示する |
| FR-005 | ショートカット変更を案内する | `割り当てを変更` から Chrome のショートカット管理画面へ案内する。拡張機能内でキーを直接書き換えない |
| FR-006 | URL 指定で保存する | 有効な URL を入力して保存でき、メタデータ取得失敗時は代替表示を使う |
| FR-007 | カテゴリを親、タグを子として管理する | activeなTagは1件のactiveな親Categoryに所属する。tombstone Tagはdeleted親を参照できるが、Tag restoreでは親Categoryを先に復元する。親Categoryは参照する全子Tag tombstoneが消滅するまで物理GCしない。子タグをBookmarkへ付ける時は親カテゴリも付け、親カテゴリを外す時はその子タグも外す。タグだけを外しても親カテゴリは残す |
| FR-008 | カテゴリはユーザーだけが作る | AI は既存カテゴリを提案できるが、作成・改名・統合できない |
| FR-009 | カテゴリ名を一意にする | 正規化後に同名のカテゴリを2件作れない。論理削除中も元IDが名前を予約し、既存カテゴリの選択、明示的な復元、または別名を促す |
| FR-010 | タグ名も一意にする | 親カテゴリをまたいで正規化後に同名のTagを2件作れない。論理削除中も元IDが名前を予約し、既存Tagの選択、明示的な復元、または別名を促す。AIは既存のユーザー定義タグを優先し、適切な既存タグがない場合だけ作る |
| FR-011 | AI 細分化度を0〜4で設定する | 設定画面ではこの項目だけラベル付きスライダーを使い、1件の分類でAIが新規作成できるTag上限をレベル0／1／2／3／4で0／1／2／4／6件とする。0でも既存カテゴリ／タグの自動付与は行う |
| FR-012 | 初回ホームと通常ホームを表示する | `runtime.onInstalled` の `reason=INSTALL` の時だけウェルカム画面を表示し、更新や開発時reloadでは再表示しない。開始操作の完了後はアクティブなBookmarkを `savedAt` 降順で表示する |
| FR-013 | 一覧をリスト／グリッドで切り替える | 追従ヘッダーの文字付きセグメントで切り替え、条件を維持する。弁当表示と表示数変更プルダウンはない |
| FR-014 | 一覧から統合キーワード検索する | ブックマーク一覧とカテゴリ・タグ一覧のどちらの追従ヘッダーからも、1つの入力でカテゴリ、タグ、Bookmarkをローカル検索し、結果は全画面検索ページへ切り替えて表示する |
| FR-015 | 件数を表示する | 現在の一覧条件に一致するブックマーク総件数と読込済み件数を区別して表示する |
| FR-016 | カテゴリを常時表示する | 各カード／行に付与済みカテゴリを常に表示する |
| FR-017 | タグを展開表示する | クリックまたはキーボードでタグを展開できる。ホバー表示はポインター環境だけの補助とする |
| FR-018 | 各Bookmarkを編集する | 各カード／行に編集ボタンがあり、モーダルで名前、URL、カテゴリ、タグを編集できる。カテゴリ入力とタグ入力を分離し、それぞれ既存候補を選択する |
| FR-019 | カテゴリ・タグ一覧を全画面表示する | 全画面一覧の追従ヘッダーに統合検索、AI検索、新規作成、管理、閉じるボタンを置き、カテゴリごとに子タグをまとめる |
| FR-020 | カテゴリ／タグから一覧へ移動する | 通常モードでカテゴリまたはタグを選ぶと対応するBookmark一覧へ移り、カテゴリIDまたはタグIDを条件として保持する |
| FR-021 | AI自然言語検索をポップアップで提供する | Bookmark一覧とカテゴリ・タグ一覧のAI操作から同じポップアップを開き、その中で入力と応答を確認する。Bookmark／カテゴリ／タグの検索に加え、Bookmationの機能や使い方に関する質問へ回答する |
| FR-022 | 検索結果を共通順で複数表示する | キーワード／AIのどちらでも `カテゴリ・タグ` を上段、`Bookmark` を下段に分ける。AI候補はスコアや順位を表示せず複数提示し、先頭へ自動遷移しない |
| FR-023 | 無限スクロールで追加読込する | 下端へ近づくたびカーソルで次ページを自動取得し、重複表示せず、失敗時はその位置で再試行できる |
| FR-024 | トップへ戻れる | ブックマーク一覧とカテゴリ・タグ一覧に、スクロール後に現れるキーボード操作可能なトップへ戻るボタンを置く |
| FR-025 | AI 失敗時も保存を守る | AI 非対応、モデル未準備、分類失敗でもタグ未設定または手動タグで保存できる |
| FR-026 | アーカイブを管理・復元する | 設定画面のアーカイブ欄にアーカイブ済みBookmarkをリスト表示し、検索とチェックボックスで選択した項目を復元できる |
| FR-027 | 入力中に最大8候補を表示する | 統合検索、Bookmark編集のカテゴリ入力、タグ入力はキーワード一致度の高い既存候補をGoogle検索型の候補リストとして合計8件まで表示し、クリックまたはキーボードで選択できる |
| FR-028 | カテゴリ／タグを連続作成する | カテゴリ・タグ一覧の `新規作成` で種類をプルダウン選択してモーダルを開く。Bookmark編集では各入力の説明横にある新規作成ボタンから同じモーダル内のサイドビューを開く。閉じるまで複数件を作成でき、Tag作成では親Categoryを必須選択する。カテゴリ／タグとも同名作成を拒否し、既存候補を選択する元画面へ戻るか別名を入力するよう案内する |
| FR-029 | カテゴリ／タグを管理モードで編集する | 一覧ヘッダーの管理ボタンで管理モードへ切り替える。管理中はカテゴリリボンまたはタグチップの選択で編集モーダルを開き、鉛筆アイコンはhover／focus時だけ表示する |
| FR-030 | 削除確認画面を挟まない | Bookmark、カテゴリ、タグの削除は確認画面を表示せず論理削除し、直後に取り消せる通知と復元経路を提供する。ただし有効な子タグが残るカテゴリの削除は実行せず、先に子タグを整理するよう案内する |

## P1 確定要件

次の機能は採用を確定する。P0のローカル保存を完成させた後に実装するが、旧資料由来の保留候補としては扱わない。既定値や競合解決方式などの未決事項だけを [ISSUES.md](ISSUES.md) で追跡する。

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-101 | 頻繁に訪問する未保存サイトを検出する | 設定画面で自動Bookmarkリマインダーを有効にし、履歴権限を許可した場合だけChrome履歴の訪問回数を読み、保存済みURLと除外URLを候補から外す |
| FR-102 | 訪問回数の閾値を数値入力する | 設定画面の単位付き数値入力で正の整数の閾値を変更でき、変更後の判定から反映する。スライダーは使わない |
| FR-103 | 閾値到達後に保存リマインダーを出す | 同じURLへの通知を重複させず、タイトル／URLと保存可否を示す。`保存` を選んだ場合だけBookmationへ保存し、`次回以降表示しない` チェック時は対象URLを以後の候補から除外する |
| FR-104 | 最近使っていないブックマークを自動アーカイブする | Chrome履歴の最終訪問日時と設定期間で判定し、期限を超えたACTIVE項目を削除せずARCHIVEDへ変更する |
| FR-105 | アーカイブまでの期間を数値入力する | 設定画面の単位付き数値入力で正の整数の日数を変更し、最終訪問日時が取得できない項目は自動変更しない。スライダーは使わない |
| FR-106 | アーカイブを最小情報で保存する | アーカイブ済み項目の利用者データはページ名、URL、カテゴリのID／表示名、タグのID／表示名／親カテゴリIDだけを保持する。復元に不可欠なBookmark ID、文字列 `archiveState`、schema version等のシステム情報は別の最小メタデータとして保持する |
| FR-107 | BookmarkをQRでユーザー間共有する | 設定画面の共有欄で、カテゴリ別、タグ別、個別Bookmarkの各単位から検索とチェックボックスで対象を選び、版付きQRを生成する。QR読取によるインポートも提供し、受信内容を確認してから専用領域へ取り込む |
| FR-108 | Google Driveで所有アカウント間共有・同期する | 同一Googleアカウントの端末間同期は `appDataFolder`、所有権または共有権限を確認できる別アカウントとの共有は通常Drive fileを使う。設定画面で対象アカウントを選び、通常fileはpermissions／capabilitiesを確認する。競合はimmutableな `syncSnapshots` と明示的なresolution planで扱い、open中はsnapshotを物理回収せず、解決後30日保持する。Label IDやedgeを暗黙にremapしない |
| FR-109 | Chrome標準ブックマークをインポートする | 明示操作と権限許可後に標準ブックマークを読み、件数と内容をプレビューしてBookmationへコピーする。元のBookmark／Folderは変更・削除しない |
| FR-110 | 右クリックから保存する | ページおよびリンクのコンテキストメニューにBookmation保存操作を表示し、許可URLを既存の保存ユースケースへ渡す |

## 非機能要件

| ID | 要件 | 基準 |
| --- | --- | --- |
| NFR-001 | プライバシー | P0 の分類と検索は端末内で完結し、ページ情報を外部 AI へ送らない |
| NFR-002 | 最小権限 | P0では標準ブックマーク・履歴・Drive権限を要求せず、P1の各機能を有効化／実行する時に目的を説明して必要な権限だけを要求する |
| NFR-003 | 可用性 | AI 非対応でも保存、編集、削除、キーワード検索、カテゴリ／タグ探索を使える |
| NFR-004 | アクセシビリティ | 主要操作をキーボードだけで行え、フォーカス、ラベル、コントラスト、live region を備える |
| NFR-005 | レスポンシブ | デザインシートのデスクトップ構成を基準にし、狭い幅でも機能を欠落させない |
| NFR-006 | データ保全 | 書込みを原子的にする。Label Normalizer v1はproject内に固定したUnicode 15.1.0のNFKC／`White_Space`／`Default_Ignorable_Code_Point`／`CaseFolding.txt` C＋Fデータだけを使い、runtime ICUへ依存しない。生成assetのhashは実装時に固定し、版付き移行とエクスポート余地を残す |
| NFR-007 | 体感性能 | カーソル取得と必要に応じた仮想化で入力・スクロールを長時間止めない |
| NFR-008 | 説明可能性 | AI作成タグ、AI検索候補、製品機能に対するAI回答を識別し、利用者が候補を修正・選択できる。AI回答を確定仕様や自動実行として扱わない |
| NFR-009 | JSONベース | Bookmark、分類、設定、共有、同期は版付きJSON互換ドキュメントを正本形式とし、Blobを別管理する |
| NFR-010 | UI Webプレビュー | 本番と同じReact／Tailwind componentをfake Adapterとfixtureで動かし、通常Webページとして主要画面・状態を確認できる |
| NFR-011 | AIエージェントE2E | 人間へ引き渡す前に、AIエージェントがビルド済みManifest V3拡張をPlaywrightで操作し、成功・失敗・skipと再現証拠を残す |
| NFR-012 | 人間による最終受入 | AIエージェントのPlaywright結果を確認後、人間が同じcommit／buildを実Chromeで確認し、承認または差戻しを記録する |

## テスト受入順序

テスト用Webプレビュー、AIエージェントによる実拡張機能のPlaywright確認、人間による最終確認の順で実施する。WebプレビューはChrome APIや拡張機能ライフサイクルの検証を代替せず、AIエージェントも人間の最終受入を代替しない。必須段階をskipした成果を完了扱いにしない。画面、fixture、証拠、隔離profile、合格条件は [TESTING.md](TESTING.md) を正本とする。

## 明示的な対象外

- Chrome 標準ブックマークや既存フォルダへの書込み（明示インポートは読み取りとBookmation側へのコピーだけを行う）
- AI によるカテゴリの作成・改名・統合
- 旧メインタグ／サブタグという利用者向け名称と、カテゴリ／タグを平坦に扱う旧モデル
- 弁当表示、グリッド列数選択、ブックマーク表示数変更プルダウン
- 右サイドタグメニュー
- AI 検索専用の全画面ページ、AI結果のスコア／順位表示、先頭候補への自動遷移
- 削除前の確認画面（代わりに論理削除、取り消し通知、復元経路を使う）
- 拡張機能内でのショートカットキー直接変更
- バックエンドサーバー、外部 LLM、常時ログイン、クラウド DB（要件で明示したGoogle Driveの `appDataFolder`／通常file連携は除く）

各数値設定の既定値、Tagの親変更、QR容量、Google Driveのアカウント間方式、インポート時のFolder対応は [ISSUES.md](ISSUES.md) で実装前に閉じる。
