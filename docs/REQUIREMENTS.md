# 要件

- 状態: 初期要件ベースライン（実装は未着手）
- 基準日: 2026-08-14

## 目的

Bookmation は、ブラウザ標準ブックマークとは別にページを素早く保存し、ユーザー定義のメインタグと AI 支援のサブタグによって、増えた項目を後から見つけ直せる Chrome 拡張機能である。UI は Plasmo（React ベース）+ Tailwind CSS で実装する。

## 出典の優先順位

要件が競合した場合は次の順に解決する。

1. 2026-08-14 の最新の依頼
2. 添付 PDF の「確定事項」（p.8）
3. 添付 PDF の「仮案」（p.5–6）
4. 参考サイトから得た着想
5. 本文書内の設計上の補完

したがって、PDF p.8 の「左にフォルダツリー」と、前回文書化した大カテゴリ・小カテゴリ階層は採用しない。拡張機能専用ブックマークをメインタグとサブタグで管理し、タグ一覧は右サイドメニューに置く。参考サイトの挙動は要件を上書きしない。

## 想定利用者と主要シナリオ

### 保存する

拡張機能アイコンをクリックすると、ポップアップに「今開いているページをブックマーク」と「Bookmation のホームを開く」の2ボタンを表示する。同じ2操作に別々のショートカットを用意する。現在ページに加え、入力した URL からも保存できる。AI が使えない場合も、タグ未設定または手動タグで保存できなければならない。

### 整理する

分類は「メインタグ」と「サブタグ」の2種類の役割だけで表し、カテゴリ階層や親子階層は設けない。メインタグを作成できるのはユーザーだけである。サブタグはユーザー定義を優先し、適切な候補がない場合にだけ AI が細分化設定の範囲内で作成できる。

各1件のブックマークにメインタグとサブタグをそれぞれ複数付与でき、同じタグは複数のブックマークで共有できる。同じ表示名のタグレコードも許可し、ID と種類で識別する。同名だけを理由に自動統合しない。

### 探す

ホームは「最近追加したブックマーク」一覧とする。利用者は右サイドメニューのタグを選び、そのタグにひも付くブックマーク一覧へ移動する。自然言語によるタグ検索とブックマーク検索は別種の結果とし、それぞれ複数候補を表示する。一覧はリスト・グリッド・弁当表示を切り替えられる。

## リリース範囲

### P0: ハッカソン向けコア

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-001 | Chrome 拡張機能として動作する | 対応 Chrome でインストールし、ライブラリ画面を開ける |
| FR-002 | 拡張機能専用のブックマークを保持する | 保存・編集・削除ができ、ブラウザ標準ブックマークを変更しない |
| FR-003 | アイコンから2つの導線を選べる | 拡張機能アイコンのポップアップに「現在ページを保存」と「ホームを開く」の2ボタンがある |
| FR-004 | 2つのショートカットを使える | 現在ページ保存用とホーム表示用を別々宣言し、どちらもキーボードから実行できる |
| FR-005 | URL を指定して保存する | 有効な URL を入力して専用ブックマークへ追加でき、取得できないメタデータには代替表示を使う |
| FR-006 | 表示用メタデータを保持する | URL、サイト名またはタイトル、ファビコン、サムネイルの取得結果、保存日時を表示できる |
| FR-007 | タグをメインとサブに分ける | カテゴリや親子階層を作らず、MAIN / SUB を平坦な役割区分として扱う |
| FR-008 | メインタグはユーザーだけが作成する | AI は既存のメインタグを候補にできるが、新規作成・改名・自動統合はできない |
| FR-009 | サブタグはユーザー定義を優先する | ユーザーがサブタグを作成でき、適切なユーザー定義候補がない場合にだけ、AI が設定上限内でサブタグを作成できる |
| FR-010 | タグの重複と複数割当を許可する | 1件に MAIN / SUB をそれぞれ複数付与でき、同名タグも作成でき、別 ID のタグを同名だけで自動統合しない |
| FR-011 | AI のサブタグ細分化度を調整する | ラベル付きスライダーで新規サブタグ作成の積極性と上限を変更でき、設定内容を説明表示する |
| FR-012 | AI 提案を人が修正できる | 保存前または保存後に割当を編集でき、AI 作成サブタグを識別できる |
| FR-013 | タグ一覧を右サイドメニューに表示する | メインタグとサブタグが表示され、タグを選ぶと対応するブックマーク一覧へ移動する |
| FR-014 | 3つの一覧形式を切り替える | リスト、グリッド、弁当の選択状態が明示され、切替後も同じ検索・タグ条件を保つ |
| FR-015 | グリッド・弁当の密度を選べる | 選択中の画面幅で有効な1行の表示数をプルダウンから選べる。リスト時はこの操作を隠すか無効にする |
| FR-016 | 各ブックマークのタグを展開表示する | リスト行とカードに展開操作があり、展開後は複数のメインタグとサブタグを区別して確認できる |
| FR-017 | 自然言語でタグを検索する | 入力に近いタグ候補を複数表示し、同名候補も ID、種類、件数で区別して選択できる |
| FR-018 | 自然言語でブックマークを検索する | 入力に近いブックマーク候補を複数表示し、候補から詳細または一覧へ移動できる |
| FR-019 | ホームで最近追加順に見る | ホームを開くと、アクティブなブックマークが保存日時の新しい順に表示される |
| FR-020 | 段階的に一覧を読み込む | スクロールで追加読込し、キーボード利用者向けの「さらに読み込む」操作も提供する |
| FR-021 | 失敗しても保存を失わない | AI 分類失敗、モデル未準備、サムネイル失敗のいずれでもタグ未設定で保存を完了できる |
| FR-022 | 手動でアーカイブ・復元する | 利用者が選んだ項目だけを一覧からアーカイブへ移し、後から元へ戻せる。履歴権限や自動判定は使わない |

### P1: PDF の追加機能

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-101 | よく訪問する未保存ページを提案する | 明示同意後に訪問回数だけを評価し、勝手に保存せず確認通知を出す |
| FR-102 | 使っていない項目を自動でアーカイブ候補にする | 最終訪問日時と設定期間で候補化し、確認後にアーカイブでき、元へ戻せる。P0 の手動アーカイブへ履歴ベースの提案を追加する |
| FR-103 | QR でユーザー間共有する | 選択項目と共有内容を確認して QR を生成し、受信側はプレビュー後に取り込める |
| FR-104 | QR 容量超過を安全に扱う | 収まらない場合は黙って切り捨てず、件数分割または後続方式が必要であると通知する |
| FR-105 | Google Drive で同一利用者の端末間同期を行う | 明示的な接続、同期状態表示、競合時のデータ保全、切断ができる |

P1 は PDF の「確定事項」に含まれるが「追加機能」と明記されているため、P0 完了後に着手する。

## 非機能要件

| ID | 要件 | 基準 |
| --- | --- | --- |
| NFR-001 | プライバシー | P0 の分類は端末内で完結し、ページ情報を外部 AI へ送信しない |
| NFR-002 | 最小権限 | P0 ではブラウザ標準ブックマーク権限を要求しない。履歴・通知・Google 認証は機能利用時に段階的に求める |
| NFR-003 | 可用性 | AI 非対応でも手動保存、URL 指定保存、右サイドメニューでの探索、閲覧、タグ編集が使える |
| NFR-004 | アクセシビリティ | 主要操作をキーボードだけで実行でき、フォーカス表示、ラベル、十分なコントラストを備える |
| NFR-005 | レスポンシブ | デスクトップを主対象とし、狭い画面では右サイドバーをドロワーまたは下部シートへ変形する |
| NFR-006 | データ保全 | 書込みは原子的に扱い、失敗時に元データを壊さず、将来のスキーマ移行とエクスポート余地を残す |
| NFR-007 | 体感性能 | 一覧は仮想化または分割取得し、入力や表示切替を長時間ブロックしない。数値目標は実データ計測後に確定する |
| NFR-008 | 説明可能性 | AI 分類結果に AI 由来表示を付け、利用者が修正・再分類できる |

## 明示的な対象外

P0 では次を実装しない。

- ブラウザ標準ブックマークや既存フォルダへの書込み・自動移行
- Chrome 以外のブラウザ対応と外部 LLM API フォールバック
- AI によるメインタグの作成・改名・統合
- 大カテゴリ、小カテゴリ、メインタグとサブタグの親子階層
- グループ共同編集、公開プロフィール、権限管理
- X など他サービスからの専用インポート
- Web ページ本文の要約
- バックエンドサーバー、常時ログイン、クラウドDB

候補機能を採用するときは [ISSUES.md](ISSUES.md) で論点を閉じ、要件 ID と受け入れ条件を追加する。
