# 要件

- 状態: 初期要件ベースライン（開発基盤のみ実装済み）
- 基準日: 2026-08-23

## 目的

Bookmation は、Chrome 標準ブックマークとは別にページを保存し、ユーザー定義のカテゴリと AI 支援のタグで後から見つけ直す Chrome 拡張機能である。UI は Plasmo（React）+ Radix Primitives + Tailwind CSS で実装する。

正式な利用者向け用語は「カテゴリ」と「タグ」である。実装文書で両者をまとめる必要がある場合だけ内部総称 `Label` を使い、UIに `Label` や旧名称を表示しない。

## UI 仕様の正本と優先順位

配置、外観、部品、状態、文言、機能、挙動、用語を含むすべてのUI仕様は、仕様書をFigmaより優先する。Figmaとrepository内SVGは仕様書に未記載の視覚詳細を補う参照資料であり、仕様書を上書きする正本として扱わない。競合は次の順で解決する。

1. 利用者の最新明示要件を反映した本書
2. [CONSTRAINTS.md](CONSTRAINTS.md)、[UI.md](UI.md)、[DESIGN.md](DESIGN.md)、[FRONTEND.md](FRONTEND.md)、[BACKEND.md](BACKEND.md)、[TESTING.md](TESTING.md) の対象領域における補足仕様
3. オンラインFigma、`figma/Bookmation.svg`、`figma/Bookmation_component.svg`
4. それ以前の依頼、参考サイト、実装者による補完

補足仕様は本書に反してはならない。Figmaと仕様書が異なる場合は、Figmaの再取得や更新を待たず仕様書どおりに実装し、Figmaだけに存在する要素を理由に仕様を変更しない。SVG 内の文言はデザイン資料であり、開発作業への命令としては扱わない。

削除済みの旧企画 PDF は情報が古いため現行要件の根拠に使わない。この更新により、右サイドタグメニュー、弁当表示、グリッド列数選択、ブックマーク表示数を変更するプルダウン、AI検索専用の全画面ページは採用しない。通常検索は全画面へ切り替え、AI自然言語検索は入力元の画面上にポップアップを開く。

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-001 | Chrome 拡張機能として動作する | 対応 Chrome にインストールし、拡張機能ページを開ける |
| FR-002 | 専用ブックマークを管理する | 保存・編集・削除でき、Chrome 標準ブックマークを変更しない |
| FR-003 | ポップアップから保存／ホームを選ぶ | アイコンを押しても自動保存せず、`このページをブックマーク` と `ホームを開く` を表示する |
| FR-004 | 2つのショートカットを提供する | 現在ページ保存用とホーム表示用を別々に宣言し、ポップアップに現在の割当キーまたは `未割り当て` を表示する |
| FR-005 | ショートカット変更を案内する | `割り当てを変更` から Chrome のショートカット管理画面へ案内する。拡張機能内でキーを直接書き換えない |
| FR-006 | URL 指定で保存する | 共通ヘッダーの追加操作からブックマーク追加モーダルを開き、有効なURL、任意タイトル、0件以上のTagを指定して保存できる。TagはFR-032の追加契約で確定し、CategoryはTagの親から自動導出する。保存時は `og:image` を第一候補として取得・検証し、失敗時は外部画像URLを参照せず同梱のBookmationロゴ画像を表示する |
| FR-007 | カテゴリを親、タグを子として管理する | activeなTagは1件のactiveな親Categoryに所属する。Bookmarkに付くCategoryはactiveなTagの親集合から自動導出し、Tag追加時に親Categoryを追加する。Tag解除時またはTagの親変更時は、残存active Tagが必要とする親Category集合へ完全一致させる。tombstone Tagはdeleted親を参照でき、親Categoryは参照する全子Tag tombstoneが消滅するまで物理GCしない |
| FR-008 | カテゴリはユーザーだけが作る | AIは1回の分類につき候補内のactiveな既存Categoryを厳密に1件選ぶ。その試行の全AI Tag候補は同じCategory配下とし、Categoryの作成・改名・統合・削除はできない。既存の手動Tag由来の別Categoryは暗黙に削除しない |
| FR-009 | カテゴリ名を一意にする | 正規化後に同名のカテゴリを2件作れない。activeな同名カテゴリがあれば既存項目の選択を促し、論理削除中の元IDが名前を予約していれば別名の入力または物理GC完了待ちを案内する |
| FR-010 | タグ名も一意にする | 親カテゴリをまたいで正規化後に同名のTagを2件作れない。activeな同名Tagがあれば信頼側で再利用し、論理削除中の元IDが名前を予約していれば新規作成しない。Gemini Nanoには、選択Category内の完全一致、同義語、正式名／略称、翻訳、表記揺れを全細分化度でREUSEし、選択Category外にだけ同等Tagがある概念はREUSE、重複CREATE、親変更をせず省くよう必須指示する。正規化名が異なる意味同等性は実モデルの品質受入条件であり、production validatorが保証する一意性はID／正規化名一致までとする。それ以外のREUSE／CREATE判断はFR-011に従う |
| FR-011 | AI 細分化度を0〜4で設定する | 新規installではAI有効・細分化度2・policy version 2のBALANCEDを初期値とする。細分化度は固定件数上限ではなく、値が低いほど関連する既存Tagの再利用へ、高いほど新規作成へ傾ける。CREATE可能範囲は0=`CORE`、1=`CORE`、2=`CORE+MAJOR`、3=`CORE+MAJOR+SUPPORTING`、4=`CORE+MAJOR+SUPPORTING+DETAIL`とする。Tag候補に件数上限を設けず、候補単位で正常なものをすべて採用する。正常候補が1件以上なら全件を適用して試行を終了し、受信済み出力の正常候補0件だけをquality-zeroとして残り枠で再試行する。最大3 dispatchすべてquality-zeroなら `NEEDS_REVIEW`、technical failureを含む枯渇は `FAILED` とする。AI無効または再設定待ちでは新規／差替えJobを作らず、保存と手動Tag編集は継続する。詳細は [AI_GUIDE.md](AI_GUIDE.md) を正本とする |
| FR-012 | 初回ホームと通常ホームを表示する | `runtime.onInstalled` の `reason=INSTALL` の時だけウェルカム画面を表示し、更新や開発時reloadでは再表示しない。開始操作の完了後はアクティブなBookmarkを `savedAt` 降順で表示する |
| FR-013 | 一覧をリスト／グリッドで切り替える | 追従ヘッダーの文字付きセグメントで切り替え、条件を維持する。弁当表示と表示数変更プルダウンはない |
| FR-014 | 一覧から統合キーワード検索する | ブックマーク一覧とカテゴリ・タグ一覧のどちらの追従ヘッダーからも、1つの入力でカテゴリ、タグ、Bookmarkをローカル検索し、結果は全画面検索ページへ切り替えて表示する |
| FR-015 | 件数を表示する | 現在の一覧条件に一致するブックマーク総件数と読込済み件数を区別して表示する |
| FR-016 | カテゴリを常時表示する | 各カード／行に付与済みカテゴリを常に表示する |
| FR-017 | タグを展開表示する | クリックまたはキーボードでタグを展開できる。ホバー表示はポインター環境だけの補助とする |
| FR-018 | 各Bookmarkを編集する | 各カード／行に編集ボタンがあり、モーダルで名前、URL、タグを編集できる。分類入力はTagだけとし、Tagの追加、一覧、解除はFR-032と同じ契約を使う。選択したactive Tagの親Categoryを保存時に自動導出し、Categoryの入力、選択、新規作成操作は置かない |
| FR-019 | カテゴリ・タグ一覧を全画面表示する | 全画面一覧の追従ヘッダーに統合検索、AI検索、新規作成、管理、閉じるボタンを置き、カテゴリごとに子タグをまとめる |
| FR-020 | カテゴリ／タグから一覧へ移動する | 通常モードでカテゴリまたはタグを選ぶと対応するBookmark一覧へ移り、カテゴリIDまたはタグIDを条件として保持する |
| FR-021 | AI自然言語検索をポップアップで提供する | Bookmark一覧とカテゴリ・タグ一覧のAI操作から同じポップアップを開き、その中で入力と応答を確認する。Bookmark／カテゴリ／タグの検索に加え、Bookmationの機能や使い方に関する質問へ回答する |
| FR-022 | 検索結果を共通順で複数表示する | キーワード／AIのどちらでも `カテゴリ・タグ` を上段、`Bookmark` を下段に分ける。AI候補はスコアや順位を表示せず複数提示し、先頭へ自動遷移しない |
| FR-023 | 無限スクロールで追加読込する | 下端へ近づくたびカーソルで次ページを自動取得し、重複表示せず、失敗時はその位置で再試行できる |
| FR-024 | トップへ戻れる | ブックマーク一覧とカテゴリ・タグ一覧に、スクロール後に現れるキーボード操作可能なトップへ戻るボタンを置く |
| FR-025 | AI 失敗時も保存を守る | AI 非対応、モデル未準備、分類失敗でもタグ未設定または手動タグで保存できる。AI出力は候補ごとに検証し、不正候補が混在しても正常候補を失わない。正常候補集合は原子的に適用し、transaction失敗では部分保存しない |
| FR-026 | アーカイブを管理・復元する | 設定画面のアーカイブ欄にアーカイブ済みBookmarkをリスト表示し、検索とチェックボックスで選択した項目を復元できる |
| FR-027 | 入力中に最大8候補を表示する | 統合検索、Bookmark追加／編集のTag入力、Tag作成／編集の親Category入力は、入力中にリアルタイムのキーワード検索を行い、一致度の高いactiveな既存候補をGoogle検索型の候補リストとして各入力8件まで表示する。クリックまたはキーボードで選択でき、自由入力文字列からCategory／Tagを暗黙作成しない |
| FR-028 | カテゴリ／タグを連続作成する | カテゴリ・タグ一覧の `新規作成` で種類をプルダウン選択してモーダルを開く。Bookmark追加／編集のTag入力とTag作成／編集の親Category入力では、説明横の新規作成ボタンから同じモーダル内のサイドビューで各対象を作成できる。Tag作成／編集では既存active Categoryの入力／選択を必須とし、Categoryをサイドビューで作成した場合はTag draftを保持して戻り、新しいCategoryを自動選択する。閉じるまで複数件を作成でき、カテゴリ／タグとも同名作成を拒否する |
| FR-029 | カテゴリ／タグを管理モードで編集する | 一覧ヘッダーの管理ボタンで管理モードへ切り替える。管理中はカテゴリリボンまたはタグチップの選択で編集モーダルを開き、鉛筆アイコンはhover／focus時だけ表示する。Category編集にはactiveな子Tagの件数と実名一覧、および関連するactive Bookmarkの重複を除いた件数を表示する。Tag編集では名前と親Categoryを変更できる。親Category入力は現在のCategoryを選択済みで開始し、別のactive Category候補を入力または選択した時点でdraftの親を置き換える。未解決の文字列はCategoryを暗黙作成せずfield errorにする。保存はTagと選択親のexpected revision、およびsubmit開始時に1回発行して同一retryで再利用する `tag-update:` requestIdを受け、新旧親、Tag、全参照active Bookmark／edgeを1 transactionで再検証し、影響BookmarkのCategory edgeを残存active Tagの親集合へ完全一致させ、Bookmark revisionと検索文書を更新する。Tag IDは維持してAI再分類は行わず、Tag名のglobal unique判定も親変更では変わらない |
| FR-030 | 種類ごとの削除規則を適用し、取り消し機能を設けない | BookmarkとTagは確認なしで即時に論理削除する。Category削除だけは、削除されるCategory、全active子Tag、影響するactive Bookmark件数と、AI有効時は再分類されることを警告する。明示確認後にCategory、全子Tag、関連edgeを同一処理で論理削除してBookmark本体を残す。AI設定がCONFIGUREDかつenabledの場合だけ影響Bookmarkを再分類し、disabled／再設定待ちはJobを作らず残存active Tag有無からCLASSIFIED／UNCLASSIFIEDにする。いずれも削除後の取り消し機能や利用者向け復元経路を提供しない |
| FR-031 | 初回用のカテゴリテンプレート機能を提供する | 初回オンボーディングで、あらかじめ用意したカテゴリ候補を利用できる機能を設ける。テンプレートの適用は利用者の明示操作として通常のCategory作成規則を通し、作成されたCategoryは `origin=USER`、名称一意、編集・削除可能とする。更新やreloadだけで既存データを追加・上書きしない。候補名、件数、選択方式、初期選択、skip、再表示、地域化、catalog versionは [ISSUE-022](ISSUES.md) で決定するまでhardcodeしない |
| FR-032 | Bookmark追加／編集でTagを1件ずつ確定する | Tag入力は開いた時と追加成功後に空欄とし、入力中のリアルタイム候補、または同じモーダルのサイドビューで新規作成して選択状態へ戻したTagを、右側の `追加` またはIME変換中ではないEnterで1件ずつdraftへ追加する。入力欄の下は `タグ n件` を左、`追加` を右に置き、現在のTagを初期状態から展開表示する。各Tagはカテゴリ・タグ一覧のTag chipと同じ形を使い、Bookmark一覧のカテゴリ・タグシェブロンと同じhover／focus時の解除UIで個別に外せる。候補選択または正規化完全一致で既存Tagへ解決できない自由入力を `追加`／Enterした場合はfield errorを表示し、Tagを暗黙作成しない。追加と編集で同じcomponent・操作契約を使う |

## P1 確定要件

次の機能は採用を確定する。P0のローカル保存を完成させた後に実装するが、旧資料由来の保留候補としては扱わない。既定値や競合解決方式などの未決事項だけを [ISSUES.md](ISSUES.md) で追跡する。

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-101 | 頻繁に訪問する未保存サイトを訪問日数で検出する | 設定画面で自動Bookmarkリマインダーを有効にし、履歴権限を許可した場合だけChrome履歴の各訪問日時を端末の暦日へ変換する。同じcanonical URLへの同日中の複数訪問は1日と数え、保存済みURLと除外URLを候補から外す |
| FR-102 | 集計期間と訪問日数閾値を設定する | 集計期間はプルダウンの `1週間`／`1ヶ月`／`1年` を、それぞれ当日を含む直近7／30／365暦日として扱う。リマインダー日数の既定値は設けずnullとする。期間を変更するたび訪問日数入力を空にし、順に1〜7／1〜30／1〜365日の正整数だけを許可する。有効な期間と閾値がそろうまで判定を停止し、スライダーは使わない |
| FR-103 | 閾値到達後に保存リマインダーを出す | 同じURLへの通知を重複させず、タイトル／URLと保存可否を示す。`はい` を選んだ場合だけBookmationへ保存する。`いいえ` を選んだ場合はそのcanonical URLの訪問日数を応答時点で0相当にリセットし、それより後の訪問日時だけで再集計する。`次回以降表示しない` チェック時は対象URLを以後の候補から除外する |
| FR-104 | 最近使っていないブックマークを自動アーカイブする | 設定のトグルをONにした場合だけ、Chrome履歴の最終訪問日時と設定期間で判定し、期限を超えたACTIVE項目を削除せずARCHIVEDへ変更する。ON操作は利用者gesture内でhistory権限を確認・要求し、未許可または要求拒否ならOFFのままエラーを表示する。実行前にも実権限を確認し、権限取消時はOFFへ戻して処理しない |
| FR-105 | アーカイブまでの期間を数値入力する | 設定画面の単位付き数値入力は既定30日とし、正の整数へ変更できる。権限許可済みでも対象URLの訪問日時を取得できない「履歴なし」は `lastVisitedAt=null` のまま `履歴がないためアーカイブできません` と項目別に表示し、そのBookmarkを自動変更しない。スライダーは使わない |
| FR-106 | アーカイブを最小情報で保存する | アーカイブ済み項目の利用者データはページ名、URL、カテゴリのID／表示名、タグのID／表示名／親カテゴリIDだけを保持する。復元に不可欠なBookmark ID、文字列 `archiveState`、schema version等のシステム情報は別の最小メタデータとして保持する |
| FR-107 | BookmarkをQR／CSVでユーザー間共有する | 設定画面の共有欄で、カテゴリ別、タグ別、個別Bookmarkの各単位から検索とチェックボックスで対象を選び、同じ固定Bookmark集合をQRコードまたはCSVとしてexportできる。QRが選択済みencoder設定の容量を超える場合は生成・分割・切捨てをせず、エラーメッセージに `CSVでエクスポート` 操作を表示する。QR読取によるインポートは提供するが、CSV importは本要件に含めない |
| FR-108 | Google Driveで所有アカウント間共有・同期する | 同一Googleアカウントの端末間同期は `appDataFolder`、所有権または共有権限を確認できる別アカウントとの共有は通常Drive fileを使う。設定画面で対象アカウントを選び、通常fileはpermissions／capabilitiesを確認する。競合はimmutableな `syncSnapshots` と明示的なresolution planで扱い、open中はsnapshotを物理回収せず、解決後30日保持する。Label IDやedgeを暗黙にremapしない |
| FR-109 | Chrome標準ブックマークをインポートする | 明示操作と権限許可後に標準ブックマークを読み、件数と内容をプレビューしてBookmationへコピーする。各Bookmarkへ取り込み時に付与するTagはそのBookmarkの直上Folder名から作る1件だけとし、祖先Folder、full path、同階層の別FolderをCategory／Tagへ変換せず、AI分類も同時実行しない。同名のactive Tagは再利用し、新規Tagは利用者がpreviewでactiveな親Categoryを選択するか同一導線でCategoryを作成してから確定する。元のBookmark／Folderは変更・削除しない |
| FR-110 | 右クリックから保存する | 一般設定の `右クリックメニューから保存` トグルを初期値ONで提供する。ONではページおよびリンクのコンテキストメニューにBookmation保存操作を重複なく登録し、許可URLを既存の保存ユースケースへ渡す。OFFではBookmation所有のmenu IDを解除し、切替直前の古いclick eventも保存へ進めない。設定変更は即時反映し、端末固有設定としてDrive同期しない |

## 非機能要件

| ID | 要件 | 基準 |
| --- | --- | --- |
| NFR-001 | プライバシー | P0 の分類と検索は端末内で完結し、ページ情報を外部 AI へ送らない |
| NFR-002 | 最小権限 | P0では標準ブックマーク・履歴・Drive権限を要求せず、P1の各機能を有効化／実行する時に目的を説明して必要な権限だけを要求する |
| NFR-003 | 可用性 | AI 非対応でも保存、編集、削除、キーワード検索、カテゴリ／タグ探索を使える |
| NFR-004 | アクセシビリティ | 主要操作をキーボードだけで行え、フォーカス、ラベル、コントラスト、live region を備える |
| NFR-005 | レスポンシブ | デザインシートのデスクトップ構成を基準にし、狭い幅でも機能を欠落させない |
| NFR-006 | データ保全 | 書込みを原子的にする。Label Normalizer v1はproject内に固定したUnicode 15.1.0のNFKC／`White_Space`／`Default_Ignorable_Code_Point`／`CaseFolding.txt` C＋Fデータだけを使い、runtime ICUへ依存しない。生成assetのhashは実装時に固定し、版付き移行とエクスポート余地を残す |
| NFR-007 | 体感性能 | カーソル取得と必要に応じた仮想化で入力・スクロールを長時間止めない |
| NFR-008 | 説明可能性 | AI作成タグ、AI検索候補、製品機能に対するAI回答を識別し、利用者が候補を修正・選択できる。AI回答を確定仕様や自動実行として扱わない |
| NFR-009 | JSONベース | Bookmark、分類、設定、共有、同期は版付きJSON互換ドキュメントを正本形式とし、Blobを別管理する |
| NFR-010 | UI Webプレビュー | 本番と同じReact／Tailwind componentをfake Adapterとfixtureで動かし、通常Webページとして主要画面・状態を確認できる |
| NFR-011 | AIエージェントE2E | 人間へ引き渡す前に、AIエージェントがビルド済みManifest V3拡張をPlaywrightで操作し、成功・失敗・skipと再現証拠を残す |
| NFR-012 | 人間による最終受入 | AIエージェントのPlaywright結果を確認後、人間が同じcommit／buildを実Chromeで確認し、承認または差戻しを記録する |

## テスト受入順序

テスト用Webプレビュー、AIエージェントによる実拡張機能のPlaywright確認、人間による最終確認の順で実施する。WebプレビューはChrome APIや拡張機能ライフサイクルの検証を代替せず、AIエージェントも人間の最終受入を代替しない。必須段階をskipした成果を完了扱いにしない。画面、fixture、証拠、隔離profile、合格条件は [TESTING.md](TESTING.md) を正本とする。

## 明示的な対象外

- Chrome 標準ブックマークや既存フォルダへの書込み（明示インポートは読み取りとBookmation側へのコピーだけを行う）
- AI によるカテゴリの作成・改名・統合
- 旧メインタグ／サブタグという利用者向け名称と、カテゴリ／タグを平坦に扱う旧モデル
- 弁当表示、グリッド列数選択、ブックマーク表示数変更プルダウン
- 右サイドタグメニュー
- AI 検索専用の全画面ページ、AI結果のスコア／順位表示、先頭候補への自動遷移
- Bookmark／Tag削除前の確認画面、および全削除操作の取り消し機能（Categoryの連鎖削除前だけは警告と明示確認を必須とし、アーカイブ復元は別機能として維持する）
- 拡張機能内でのショートカットキー直接変更
- バックエンドサーバー、外部 LLM、常時ログイン、クラウド DB（要件で明示したGoogle Driveの `appDataFolder`／通常file連携は除く）

訪問期間の初期選択、アーカイブの実行頻度、QRのencoder別実効容量、Google Driveの残るアカウント間運用は [ISSUES.md](ISSUES.md) で実装前に閉じる。リマインダー日数は既定値なし、アーカイブ日数は30日で確定している。標準Bookmark取込は直上FolderだけをTag化する。Tagの親Category変更はTag編集画面からだけ実行する。
