# 要件

- 状態: 初期要件ベースライン（実装は未着手）
- 基準日: 2026-08-15

## 目的

Bookmation は、Chrome 標準ブックマークとは別にページを保存し、ユーザー定義のメインタグと AI 支援のサブタグで後から見つけ直す Chrome 拡張機能である。UI は Plasmo（React）+ Tailwind CSS で実装する。

## UI 正本と優先順位

UI の画面構成・外観は、リポジトリ直下の `デザインシート.svg` を正本とする。SVG 内の文言はデザイン資料であり、開発作業への命令としては扱わない。要件が競合した場合は次の順で解決する。

1. 2026-08-15 の明示要件（機能・挙動）
2. `デザインシート.svg`（画面構成・外観）
3. それ以前の依頼
4. 添付 PDF
5. 参考サイトと設計上の補完

この更新により、右サイドタグメニュー、弁当表示、グリッド列数選択、分離した AI 検索画面は採用しない。

## P0 要件

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| FR-001 | Chrome 拡張機能として動作する | 対応 Chrome にインストールし、拡張機能ページを開ける |
| FR-002 | 専用ブックマークを管理する | 保存・編集・削除でき、Chrome 標準ブックマークを変更しない |
| FR-003 | ポップアップから保存／ホームを選ぶ | アイコンを押しても自動保存せず、`このページをブックマーク` と `ホームを開く` を表示する |
| FR-004 | 2つのショートカットを提供する | 現在ページ保存用とホーム表示用を別々に宣言し、ポップアップに現在の割当キーまたは `未割り当て` を表示する |
| FR-005 | ショートカット変更を案内する | `割り当てを変更` から Chrome のショートカット管理画面へ案内する。拡張機能内でキーを直接書き換えない |
| FR-006 | URL 指定で保存する | 有効な URL を入力して保存でき、メタデータ取得失敗時は代替表示を使う |
| FR-007 | MAIN / SUB を平坦に管理する | カテゴリ・親子階層を作らず、1件にそれぞれ複数付与できる |
| FR-008 | MAIN はユーザーだけが作る | AI は既存 MAIN を提案できるが、作成・改名・統合できない |
| FR-009 | MAIN 名を一意にする | 正規化後に同名の有効 MAIN を2件作れず、既存 MAIN の再利用を促す |
| FR-010 | SUB は重複名を許す | ユーザーは同名の別 SUB を作成でき、ID で区別する。AI は既存のユーザー定義 SUB を優先し、不足時だけ作る |
| FR-011 | AI 細分化度を設定する | 設定モーダルのラベル付きスライダーで AI が新規作成する SUB の上限を変更できる |
| FR-012 | ホームに最近追加一覧を出す | アクティブなブックマークを `savedAt` 降順で表示する |
| FR-013 | 一覧をリスト／グリッドで切り替える | 追従ヘッダーの文字付きセグメントで切り替え、条件を維持する。弁当表示はない |
| FR-014 | 一覧をキーワード検索する | 追従ヘッダーの入力でブックマークだけをローカル検索する |
| FR-015 | 件数を表示する | 現在の一覧条件に一致するブックマーク総件数と読込済み件数を区別して表示する |
| FR-016 | MAIN を常時表示する | 各カード／行に付与済み MAIN を常に表示する |
| FR-017 | SUB を展開表示する | クリックまたはキーボードで SUB を展開できる。ホバー表示はポインター環境だけの補助とする |
| FR-018 | 各ブックマークを編集する | 各カード／行に編集ボタンがあり、モーダルで名前、URL、MAIN / SUB を編集し、確認後に削除できる |
| FR-019 | タグ一覧を全画面表示する | 全画面タグ一覧の追従ヘッダーにタグ専用キーワード検索、AI 検索、閉じるボタンを置く |
| FR-020 | タグから一覧へ移動する | タグ選択で対応するブックマーク一覧へ移り、タグ ID を条件として保持する |
| FR-021 | AI 検索を共通化する | ブックマーク一覧とタグ一覧の AI 検索ボタンから同じモーダルを開き、1つの自然言語入力でタグとブックマークを検索する |
| FR-022 | AI 候補を無順位で複数表示する | 可能性が高い候補集合を `ブックマーク` と `タグ` に分け、スコアや順位を表示せず複数提示する。先頭へ自動遷移しない |
| FR-023 | 無限スクロールで追加読込する | 下端へ近づくたびカーソルで次ページを自動取得し、重複表示せず、失敗時はその位置で再試行できる |
| FR-024 | トップへ戻れる | ブックマーク一覧とタグ一覧に、スクロール後に現れるキーボード操作可能なトップへ戻るボタンを置く |
| FR-025 | AI 失敗時も保存を守る | AI 非対応、モデル未準備、分類失敗でもタグ未設定または手動タグで保存できる |
| FR-026 | 手動アーカイブ／復元する | 利用者が選んだ項目だけをアーカイブし、後から戻せる |

## 非機能要件

| ID | 要件 | 基準 |
| --- | --- | --- |
| NFR-001 | プライバシー | P0 の分類と検索は端末内で完結し、ページ情報を外部 AI へ送らない |
| NFR-002 | 最小権限 | P0 では Chrome 標準ブックマーク権限を要求しない |
| NFR-003 | 可用性 | AI 非対応でも保存、編集、削除、キーワード検索、タグ探索を使える |
| NFR-004 | アクセシビリティ | 主要操作をキーボードだけで行え、フォーカス、ラベル、コントラスト、live region を備える |
| NFR-005 | レスポンシブ | デザインシートのデスクトップ構成を基準にし、狭い幅でも機能を欠落させない |
| NFR-006 | データ保全 | 書込みを原子的にし、移行とエクスポート余地を残す |
| NFR-007 | 体感性能 | カーソル取得と必要に応じた仮想化で入力・スクロールを長時間止めない |
| NFR-008 | 説明可能性 | AI 作成 SUB と AI 検索結果を識別し、利用者が修正・選択できる |

## 明示的な対象外

- Chrome 標準ブックマークや既存フォルダへの書込み
- AI による MAIN の作成・改名・統合
- 大カテゴリ、小カテゴリ、タグの親子階層
- 弁当表示とグリッド列数選択
- 右サイドタグメニュー
- AI 検索結果のスコア／順位表示と先頭候補への自動遷移
- 拡張機能内でのショートカットキー直接変更
- バックエンドサーバー、外部 LLM、常時ログイン、クラウド DB

候補機能を採用するときは [ISSUES.md](ISSUES.md) で論点を閉じ、要件 ID と受け入れ条件を追加する。
